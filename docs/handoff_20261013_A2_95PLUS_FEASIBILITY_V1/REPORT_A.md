# 按95+目标重新审查当前方案

账户A（新接手）独立审核与交付，A2。2026-10-13。沿用A2B-024及已完成部署审核，只做匿名误差预算分析，不训练。

结论：当前冻结R1在已给测试集上的C1改进空间为零，因为所有测试井使用保持不变的B0。A2已比较实际新旧CSV，120个已输出预测相同。继续改C1、重复打包或同配置确定性训练，不能形成当前提交的95+路径。

如果“这套方案”指整个ExtraTrees、历史特征及目标表示框架，可继续研究，但目前没有足以支持95+的证据，也没有证据证明整个模型家族永远达不到95。当前可签署的是“冻结路由方向不足；总体框架的95+潜力尚未证实”，不能给可信成功概率。必须改到实际服务测试井的B0或有效输入表示，而不只是提高未覆盖测试群的验证分。

## 95需要多大的改变

按官方Score=100*(1−平均井加权损失)，用户报告86.2003对应损失0.137997，95对应0.05。需要净增8.7997分、消除现有损失的63.7673%。这是从报分推导的条件预算，不是A2独立读取的隐藏标签或平台记录。两次86.2003继续分别留档，平台包与记录的独立绑定仍未完成。

固定安全OOF73.714107对应损失0.262858927；若在这批验证上达到95，需消除80.9784%的损失。不能要求CV一定95才可能平台95，二者样本不同；这项计算用于检查改进机制的数量级，不能把CV分差加到榜单分数。

## 下一轮审查必须改变的重点

先看候选是否能改变正尺度井的B0预测，再看收益来自什么误差，最后看其在未查看过的确认切分是否稳定。当前五组正尺度井贡献约78%—81%的总损失，前两月约75%；正尺度与前两月交叉损失的数学下界约54%—57%，但这不是已观测交叉切片。95研究应关注前四月的整体误差预算，不把任务自动缩成“只训练前两月”。

过预测和欠预测都贡献大量早期损失，不能只凭总体过预测稍多就统一下调。下一批应报告预测前状态×月份×过/欠预测的匿名交叉损失、井等权贡献、跨折方向和收益集中程度。无法从合法预测前信息辨识的标签后验分组只能诊断，不能训练路由。

一个低成本、可证伪的首步仍可采用同325特征、同缩放log目标、完整12月池化ExtraTrees，只改变squared_error为absolute_error，并对B0正尺度群和前四月分别检查。它用于检验叶估计稳健性机制，不称为95方案，也不在本轮执行。模型改动前先查历史候选，避免换名重复。方法事实见[scikit-learn官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.ExtraTreesRegressor.html)。

若只能得到零点几分，结论应是局部增益，不能因通过原+0.20筛选门槛就把95机会判为已证实。应进一步判断预测前历史与响应之间是否有更强的可辨识信息：在训练折内处理特征后，相似预测前状态的井是否仍有大幅不同的早期标签、是否存在可合法提取的状态/事件解释。这是待授权的数据诊断；相似输入的标签分散只能提示信息不足，不能单独证明不可约误差或硬上限。

当不同模型已获得同边界、同折真实OOF时，可检查它们是否在正尺度和前四月存在稳定互补，再设计折内或严格嵌套融合。不能把多个小增益相加，不能在全体OOF上找融合系数后把同一OOF称为验证。没有互补证据时，增加模型数或深度学习复杂度没有95依据。

若连续受控实验只得到小幅、切分敏感收益，又没有新的可用信息或互补机制，应重新思考表示与学习目标，停止扩大同一树参数网格。当前不能直接批准“不断训练直到95”，因为95也受输入信息和样本支持约束。
