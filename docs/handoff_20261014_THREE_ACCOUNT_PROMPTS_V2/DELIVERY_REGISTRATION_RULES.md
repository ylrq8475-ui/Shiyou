# 交付登记规则（三账户共用，2026-10-14 用户批准）

目的：避免出现"已交付，但位置不明、审核结论不明，无法判断"的情况。B、Codex、Claude 三份 Prompt 都引用本文件，以本文件为准。

## 规则 1：报告首部必须有《交付登记卡》

B 的每份交付报告、Codex 的每份审核报告，第一节必须是下面这张卡，字段不得删减。不适用的字段写"不适用"，不能留空。

```
【交付登记卡】
任务编号/阶段：
角色：B 交付 / Codex 审核
分支：
完整提交号（40 位）：
目录路径：
结果文件路径（单个 JSON）：
关键数字（按决策表变量逐项列出，变量名与决策表一致）：
硬门禁结论：泄漏 / 错位 / 井级隔离 / 指标 —— 各自 通过/失败/UNKNOWN
UNKNOWN 与未关闭项：编号、等级（P0–P3）、所缺证据
对应决策表行（仅 Codex 填写；B 写"不适用"）：
```

- Codex 审核报告的卡中，"完整提交号"填写 Codex 报告自身的提交号，另起一行写"被审 B 提交号（40 位）"。
- 登记卡缺任一字段时，Claude 不作判断，直接退回补齐。

## 规则 2：用户转发给 Claude 时的最少内容

需要 Claude 给出下一步时，用户转发的内容至少要有三样：

1. Codex 审核报告的链接，链接里要带完整提交号；
2. Codex 登记卡中的"硬门禁结论"和"对应决策表行"；
3. B 结果 JSON 的链接，链接里要带完整提交号。

只说"已交付"而不带这三样时，Claude 只回复缺哪几项，不推测、不搜仓库。

## 规则 3：链接必须固定到提交号

所有交付和审核链接都必须使用 `/blob/<40位提交号>/` 或 `/tree/<40位提交号>/` 的形式。只给分支名、main 或短提交号的链接，视为未提供。

## 规则 4：UNKNOWN 分级处理

| 等级 | 含义 | 对下一步的影响 |
|---|---|---|
| P0 | 可能涉及泄漏、错位、井级隔离或指标错误 | 等同硬门禁失败，立即停止 |
| P1 | 影响结论可信度的关键证据缺失 | 等同失败，阻断下一步，先补证 |
| P2 | 非核心证据缺失，例如覆盖面、记录不全 | 不阻断方案起草；阻断下一阶段的训练批准，补齐后才能批准 |
| P3 | 形式或记录瑕疵 | 只记录，不阻断 |

- Codex 必须为每个 UNKNOWN 标出等级和所缺证据。
- 存在任何未关闭的 UNKNOWN 时，总结论不能写成"全部通过"。
