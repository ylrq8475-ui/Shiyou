# Shiyou 账户B交付规则 v1

生效日期：2026-10-10（Asia/Shanghai）。适用范围：本项目账户B后续交接。依据：用户要求任务完成后自动上传GitHub，并将本次交付方式定为新规则。

## 默认交付流程

1. 完成已获授权的任务后，在本机独立版本目录整理可交接成果；失败或按计划停止也是应交付的有效结论。
2. 使用明确文件清单检查匿名性、隐私与凭据，并核对文件及压缩包内部内容；保存原始字节SHA256清单。
3. 自动发布到[现有项目仓库](https://github.com/ylrq8475-ui/Shiyou)的专用交接分支和版本目录。常规整理、核验、上传不再逐次申请批准；不要求另建仓库。
4. 从GitHub按实际提交号回取文件，逐项比较SHA256、字节数和文件清单，核对提交改动范围。只有上传及远程校验均成功，才报告“GitHub交付完成”。
5. 向用户提供固定提交链接、完整提交号、交接目录、主要报告、复测包及其SHA256、校验结果和账户A独立复核状态。账户间协作请求随交接材料提供，由用户转交。

## 身份与发布通道

- 交接README、报告、索引和提交说明明确注明“账户B执行与交付”；GitHub发布登录账户可以是用户已授权的`ylrq8475-ui`，不改变账户B身份。
- 账户A继续独立审计，尚未收到验收时如实写为PENDING，不把B自检或上传成功写成A验收通过。
- 优先使用可用、已授权的发布通道。目前已验证的是用户登录后的GitHub网页上传；浏览器与命令行凭据分别核验。历史CLI 403不能用来否定可用的网页通道。
- 登录或双重验证确需用户操作时，仅报告实际所需动作；不索取密码、验证码、恢复码，不绕过安全控制。

## 可发布材料与保留边界

- 可发布：通过检查的匿名聚合报告、协作请求、计划与实现说明、合成检查、环境版本、公开适用源码、哈希清单及匿名只读复测包。
- 不发布：赛事原始数据、真实井标识符、候选原值、原始行、逐井标签或预测、逐行OOF、私有资源包、冻结私有配置内容、模型权重、凭据或令牌。上传目录必须按清单选取，禁止直接上传整个工作目录。
- 新成果放入独立版本目录；保留旧代码、计划、实施锁、模型、结果和正式ZIP，不覆盖冻结成果，不为发布改变既有指标或回填历史证据。
- 此规则仅授权交付，不新增训练、候选搜索、部署、模型升级、正式赛事打包或平台提交授权；不自动合并PR，不直接联系账户A。

## 异常与修订

- 权限、网络、隐私或远程校验失败时，保留本地成果，说明具体阻断及所需动作；不得把“已尝试上传”报告为完成。
- 修订已交付成果时新增版本，列明变动和旧版本关系，不覆盖旧版本。本规则后续变更同样版本化；用户更新指令优先。
- 自动交付发生于本执行端处理任务期间；本规则不代表已创建后台定时任务或可在退出后持续运行。
