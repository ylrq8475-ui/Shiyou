# 替代账户A匿名GitHub交付规则 V1

账户B按用户本轮“新账户正确审核并一样可以提交GitHub”要求整理；这是接手交付范围，不代表A已验收或取得任何新训练权限。继续使用https://github.com/ylrq8475-ui/Shiyou，无需新仓库。

1. 新A完成本轮已授权只读审核后，自动发布经过检查的匿名材料，署名**账户A（替代接手）独立审核与交付**。使用独立A审核分支及新版本目录，建议`codex/a2b024-a-successor-review-20261012`和`docs/handoff_20261012_A2B024_A_SUCCESSOR_REVIEW_v1`；执行时先检查是否已存在，存在则核对归属与状态，不能静默覆盖。不要在B交付分支写审计结论，不覆盖旧A回函，不修改main，不合并PR。
2. 先核验实际GitHub登录及仓库写权限。可沿用用户已授权且已登录的ylrq8475-ui；若登录其他GitHub账号，需该仓库协作者写权限。网页登录与CLI凭据分别判断，CLI 403不证明已登录网页不能发布。正常登录/二次验证需要人操作时，只说明具体操作；不索取密码、验证码或令牌，不复制B的凭据，不绕过安全控制。
3. 先完成具体可审核报告、独立算术/合成记录、审核范围、结论、缺项、协作回复及SHA256。匿名性检查必须包含明确上传白名单和ZIP内成员，禁止直接上传整个工程。
4. 只发布匿名聚合、公开适用源码、复测入口/日志、来源摘要、计划对照、审核结论和清单。不发布赛事CSV、私有配置原文、原始行、真实井号、逐井标签/预测、逐行OOF、模型权重、私有资源包、凭据。公共审核文件可以引用私有文件名与摘要，但不能把其内容粘贴进去。
5. 上传后按**实际完整提交号**回取每项公开文件，比对原始字节SHA256、字节数和文件集合；核对提交只新增预期A目录，既有A/B证据保持不变。ZIP核对CRC、成员路径及内外清单。未完成回取核验只能写“已上传待核验”或“发布受阻”，不能宣称交付完成。
6. 最终给用户固定提交链接、完整提交号、报告/协作回复、匿名复测包及其SHA256、远程核验结果、自己实际执行的检查与未执行范围。若浏览器用于发布，保留可核对页面作为交付证明。所有角色与署名一致，不把GitHub登录人当审计独立性的证明。
7. 审核结论可为不同意、部分同意或同意，失败结论同样交付。此规则不要求A同意B、不授权训练/模型升级/正式赛事打包/平台上传。需要通知B时生成可由用户转发的协作回复，不直接向其他聊天、邮箱等发送消息。

已有B交付规则固定来源：ff0f6b44ed543dc689d1b9c12a9112877adb9801，docs/coordination_B/HANDOFF_DELIVERY_RULES_V1.md。本规则沿用匿名白名单、独立版本和远程回取原则，替代A的新增交付许可来自用户本轮明确要求。
