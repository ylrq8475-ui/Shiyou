# 交付登记规则（三账户共用；规则 1–4 于 2026-10-14 15:05 批准，规则 5 于 2026-10-14 16:30 批准，规则 6 于 2026-10-14 16:45 批准）

目的：避免出现"已交付，但位置不明、审核结论不明，无法判断"的情况。B、Codex、Claude 三份 Prompt 都引用本文件，以本文件为准。

## 规则 1：报告首部必须有《交付登记卡》

B 的每份交付报告、Codex 的每份审核报告，第一节必须是下面这张卡，字段不得删减。不适用的字段写"不适用"，不能留空。

```
【交付登记卡】
任务编号/阶段：
角色：B 交付 / Codex 审核
分支：
完整提交号（40 位）：
目录路径：
结果文件路径（单个 JSON）：
关键数字（按决策表变量逐项列出，变量名与决策表一致）：
硬门禁结论：泄漏 / 错位 / 井级隔离 / 指标 —— 各自 通过/失败/UNKNOWN
UNKNOWN 与未关闭项：编号、等级（P0–P3）、所缺证据
对应决策表行（仅 Codex 填写；B 写"不适用"）：
所依据的 Claude 指令存档提交号（40 位）：
```

- Codex 审核报告的卡中，"完整提交号"填写 Codex 报告自身的提交号，另起一行写"被审 B 提交号（40 位）"。
- 登记卡缺任一字段时，Claude 不作判断，直接退回补齐。

## 规则 2：用户转发给 Claude 时的最少内容

需要 Claude 给出下一步时，用户转发的内容至少要有三样：

1. Codex 审核报告的链接，链接里要带完整提交号；
2. Codex 登记卡中的"硬门禁结论"和"对应决策表行"；
3. B 结果 JSON 的链接，链接里要带完整提交号。

只说"已交付"而不带这三样时，Claude 只回复缺哪几项，不推测、不搜仓库。

## 规则 3：链接必须固定到提交号

所有交付和审核链接都必须使用 `/blob/<40位提交号>/` 或 `/tree/<40位提交号>/` 的形式。只给分支名、main 或短提交号的链接，视为未提供。

## 规则 4：UNKNOWN 分级处理

| 等级 | 含义 | 对下一步的影响 |
|---|---|---|
| P0 | 可能涉及泄漏、错位、井级隔离或指标错误 | 等同硬门禁失败，立即停止 |
| P1 | 影响结论可信度的关键证据缺失 | 等同失败，阻断下一步，先补证 |
| P2 | 非核心证据缺失，例如覆盖面、记录不全 | 不阻断方案起草；阻断下一阶段的训练批准，补齐后才能批准 |
| P3 | 形式或记录瑕疵 | 只记录，不阻断 |

- Codex 必须为每个 UNKNOWN 标出等级和所缺证据。
- 存在任何未关闭的 UNKNOWN 时，总结论不能写成"全部通过"。

## 规则 5：固定索引文件 `handoff-index/LATEST.json`

- 仓库设固定分支 `handoff-index`，只放一个文件 `LATEST.json`，作为每轮交付和审核的唯一索引。
- B、Codex 每次发布并按字节核对后，在 `entries` 末尾**追加**一条记录，不得修改或删除已有记录。
- Claude 发布每轮指令存档后，也追加一条记录（见规则 6）。
- 每条记录的字段：

```json
{
  "task": "A2B-026/路线B-B2",
  "role": "B | Codex | Claude",
  "commit": "40 位提交号",
  "report_path": "报告路径",
  "result_json_path": "结果 JSON 路径（Claude 记录写 不适用）",
  "reviews_commit": "Codex 填被审 B 提交号；其他角色写 不适用",
  "hard_gates": "泄漏/错位/井级隔离/指标 各自 通过|失败|UNKNOWN（B 自报，Codex 终判；Claude 写 不适用）",
  "decision_row": "仅 Codex 填写；其他角色写 不适用",
  "open_unknowns": ["编号 等级 所缺证据"],
  "published_at": "ISO 8601 时间（+08:00）"
}
```

- 用户只需说"新一轮已完成"，Claude 就只读 `handoff-index/LATEST.json`，再按其中登记的路径读 Codex 报告和 B 的结果 JSON。不扫描其他分支。
- 同一任务没有 Codex 记录，或 Codex 记录的 `reviews_commit` 与最新 B 记录的 `commit` 不一致时，Claude 只回复"Codex 未完成"或"审核对象不一致"，不作判断。
- 用户直接转发链接（规则 2）仍然有效；两者冲突时以用户转发为准，并请 Codex 更正索引。

## 规则 6：Claude 的指令原文必须入库

- Claude 每轮给 B 的指令和给 Codex 的必审清单，在用户批准后，**逐字**存入 `docs/handoff_<日期>_<任务>_CLAUDE_INSTRUCTIONS_<轮次>/INSTRUCTION_ORIGINAL.md`，并附用户批准原话。
- 存档后在 `handoff-index/LATEST.json` 追加 Claude 记录。B 和 Codex 以该文件为指令原文来源，不再依赖跨会话转述。
- B 的交付和 Codex 的审核，都要在登记卡中写明所依据的指令存档提交号（40 位）。
- 存档只记录原文，不新增授权；执行范围仍以用户批准原话为准。
